Chapter 1 · Getting started

What GitHub is, in plain English

GitHub is a website where people keep documents and track every change made to them. Think of it as a shared notebook with a built-in time machine:

  • You can see who changed what, when, and why.
  • You can go back to an older version if something goes wrong.
  • Many people can work on the same document without overwriting each other.

You do not need to write code to use GitHub. This manual uses only the website and, optionally, a free desktop app.

Why healthcare workers use GitHub

Healthcare teams create and update documents all the time:

  • Clinical protocols and workflow checklists
  • Shift sheets and scheduling templates
  • Orientation packets for new staff
  • Policy and procedure documents

Without a system like GitHub, teams often end up with files named Protocol_FINAL_v2_REALLYFINAL.docx and no one knows which one is current. GitHub solves that by keeping one official copy and a complete history of every change.

The three ideas you need to know

Only three ideas cover almost everything you will do in this manual:

  1. Repository (repo) — One folder for one project. For example, a repo called "Unit Protocols" holds all your protocol documents.
  2. Commit — Saving a snapshot of the repo with a short note about what changed. Every commit is stored forever, so you can always look back.
  3. Branch — A separate working copy where you can draft changes without touching the official version. When the draft is ready, you merge it back.

Everything else — accounts, sharing, templates — builds on these three ideas.

No-code versus code

This manual shows you how to use GitHub through the website and GitHub Desktop (a free app with buttons and menus). You never have to type code or use a terminal. If you ever want to go deeper, those options exist, but they are not required.

Your first step

Start with the next chapter to create your GitHub account. Then work through the chapters in order. Each one walks through one real-world task: documenting protocols, sharing templates, and version-controlling shift sheets.

A privacy reminder before you begin

GitHub is not the place for patient information. Never upload names, medical record numbers, photos, or anything that could identify a patient. Read Chapter 6 (Privacy and Safety) before you upload any work document.
