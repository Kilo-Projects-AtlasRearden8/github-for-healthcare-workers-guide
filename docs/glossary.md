# Glossary

Plain-English definitions of the GitHub terms used in this manual.

## Commit
A saved snapshot of a repository, with a note about what changed. Every commit
is stored forever, so you can always look back at older versions.

## Collaborator
Someone you invite to your repository. You choose whether they can only view
(Read) or also edit (Write).

## Merge
Combining changes from one branch into another. For example, merging a draft
protocol into the main version once it is finished.

## Private repository
A repository that only you and invited collaborators can see. Public
repositories can be seen by anyone on the internet.

## Pull request
A request to review and merge changes. Not used in this manual, but you may
see it on GitHub.

## Push
Sending saved changes from your computer to GitHub. Not used in this manual
because everything here happens on the website.

## README
The front page of a repository, usually explaining what the project is and how
to use it.

## Repository (repo)
One folder for one project, such as "Unit Protocols" or "Shift Sheets." It
holds all the files and the full history of changes.

## Markdown
A simple way to format text using plain characters. For example, `# Heading`
makes a heading, and `- Item` makes a list item. Files end in `.md`.

## Branch
A separate working copy of a repository where you can draft changes without
touching the official version. Not used in this manual, but you may see it on
GitHub.

## Fork
A copy of someone else's repository under your own account. Not used in this
manual.
